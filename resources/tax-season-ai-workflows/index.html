A note on the writing

The setup steps and the "Check it" steps are written in simplified technical English: short sentences, one action per step, no contractions. They're meant to be followed exactly. The rest reads like I talk.

Set It Up

Set it up once, before the first organizer goes out

Do this in November. Once the season starts, nobody has an afternoon.

The plan

Use Claude Team or Enterprise for client work, so it sits under business terms, isn't used to train Claude's models, and the firm controls who has access. Check current plans and prices at claude.com/pricing. Turn on file creation, because several workflows hand back an Excel file or a Word letter.

  1. Open Settings (on Team and Enterprise, the owner opens Organization settings).
  2. Select Capabilities.
  3. Turn on Code execution and file creation.

One project per workflow

Make a Claude project for each workflow you roll out, and paste the workflow's standing instructions into the project instructions. Then everyone runs the same steps the same way, and the reviewer knows what to expect. Name them with a number, so they sort in season order: 01 Organizer Sender, 02 Document Chaser and so on.

  1. In Claude, select Projects.
  2. Select New project.
  3. Name the project, for example 03 Document Reader.
  4. Paste the standing instructions from the workflow into the project instructions.
  5. Add the firm's templates to the project files: letters, checklists, the organizer.
  6. On Team, share the project with the people in the workflow's "Who runs it" row.

The data rule

Every workflow card says which tier of client data can go in. Write the rule down once, put it in the firm's WISP, and make it the first line of every project's instructions.

TierWhat it coversRule
Tier 1: neverFull Social Security numbers, bank and card numbers, ID images, passwords, IRS PINsNever goes into any AI tool. Redact it before upload, or use the last four digits.
Tier 2: with consentTax return information: the return, the source documents, the workpapers, IRS noticesOnly in the firm's business account, only where the firm's Section 7216 setup covers it, and only by the people on the workflow.
Tier 3: free to useFirm templates, checklists, anonymized examples, counts and codesUse it anywhere in the firm's business account.

Section 7216. A return preparer generally needs the client's written consent before using or disclosing tax return information for purposes other than preparing the return (26 CFR 301.7216-3). Some of these workflows prepare the return. Some, like the planning signal list, go beyond it. Take the question of which is which to the firm's adviser before the season, not during it, and write the answer into the engagement letter.

Workflow 1

The Organizer Sender

At a glance
WhenDecember, before the holidays
Who runs itAdmin
Who reviews itManager, on a sample of five
Client data that can go inTier 3 for the letters. Tier 2 only for the client list with return types
What comes backAn engagement letter, a Section 7216 consent and the right organizer for each client, ready to send

The season starts late when the organizer goes out in February. This one sends the engagement letter, the consent and the organizer together, matched to what each client filed last year.

Prompt · Build the December send list
The attached list is last year's clients, by client code, with the forms we filed for each (1040, Schedule C, Schedule E, 1120-S, 1065, state returns) and the fee.

For each client:
1. Pick the organizer version from the project files: individual, individual with business, individual with rentals, or business entity.
2. Pick the engagement letter template that matches the return types.
3. Note anything that changed last year that the letter or organizer must cover: a new state, a new entity, a K-1 that arrived late, a return we extended.
4. Flag any client with no signed Section 7216 consent on file.

Give me one table: client code, organizer, letter, notes, consent status.
Do not write to any client. Do not invent a fee change.

Check it

  1. Open five rows at random. Compare each with last year's return.
  2. Confirm every client with an extension last year has a note.
  3. Send only after the manager signs off the sample.
✓
Result

Every client gets the right letter and organizer in December, and the list of missing consents goes to the partner before any return information goes near an AI tool.

Where it goes wrong

A client who added a rental or a state in the year gets last year's organizer. The notes column is there to catch it, so read it.

Workflow 2

The Document Chaser

At a glance
WhenEvery Monday, February to April
Who runs itAdmin
Who reviews itSenior, for the first round of each client
Client data that can go inTier 2: last year's document list and this year's portal index, by client code
What comes backA missing-documents list per client and the reminder email in the firm's tone

Last year's return is the best checklist you have. Every W-2, 1099 and K-1 that was there last year should turn up again, or someone should know why it didn't.

Prompt · What's still missing
For client [CODE]:
- Last year's document list is attached (payer and form type for every source document we used).
- This year's portal index is attached (file names and dates received).

1. Match this year's documents to last year's, payer by payer.
2. List what is missing. For each item: payer, form type, and whether it usually arrives late (K-1s, corrected 1099s).
3. List anything new this year that wasn't there last year.
4. Draft a short reminder email in the firm's tone from the project files. Name each missing document by payer and form. Do not list documents we already have.

If a file name does not tell you the payer, say so. Do not guess.

Check it

  1. Compare the missing list with the portal for one client each week.
  2. Read the email before it goes. Check every payer name.
Where it goes wrong

A payer whose name changed, a bank merger for example, shows up as one missing and one new. Read the "new this year" list next to the missing list.

Workflow 3

The Document Reader

At a glance
WhenAs documents arrive
Who runs itStaff accountant
Who reviews itSenior, on every flagged document and a sample of the rest
Client data that can go inTier 2, with Social Security numbers and account numbers redacted (Tier 1)
What comes backA table of every box on every form, with a flag on anything it couldn't read

This is the hours. Keying W-2s, 1099s, 1098s and K-1s into a worksheet is the most repeated job in the season, and the one where a tired person transposes two digits.

Standing instructions · Document Reader project
You read US tax source documents for a CPA firm: W-2, 1099-INT, 1099-DIV, 1099-B, 1099-NEC, 1099-MISC, 1099-R, 1098, 1098-T, Schedule K-1 (1065, 1120-S, 1041).

For every document:
- Record the form type, the payer or issuer, the tax year and every box with a value, box by box, exactly as printed.
- If the form is marked CORRECTED, say so on its own line.
- If a box is unreadable, blurred, cut off or handwritten, write UNREADABLE for that box. Never estimate a number.
- If the tax year is not the year we are preparing, flag it.
- For consolidated brokerage statements, record the summary totals and list the pages you read.

Output one row per box: client code, form, payer, box number, box label, amount, flag.
Data rule: if you see a full Social Security number or account number, do not repeat it. Write REDACT and tell me which page.

Check it

  1. Open every row with a flag and read the box on the source document yourself.
  2. For each client, add up wages and withholding from the table. Compare the totals with the documents.
  3. Check one random box on every third document.
✓
Result

A table the preparer can import or key from in minutes, and a short list of the documents a person must read.

Where it goes wrong

Photographed documents with a shadow across a box, and K-1 footnotes that carry the real information. The UNREADABLE flag catches the first. Tell the preparer to read every K-1 footnote page themselves.

Workflow 4

The Prior-Year Comparison

At a glance
WhenWhen the draft return is ready
Who runs itStaff accountant
Who reviews itSenior
Client data that can go inTier 2: this year's draft and last year's return, by client code
What comes backA line-by-line comparison and a list of every swing over your threshold

The 1099 that disappeared is the one the IRS notices later. This compares the draft with last year line by line, before a reviewer spends time on it.

Prompt · Compare with last year
Compare this year's draft return for [CODE] with last year's return, both attached.

1. Line by line: last year, this year, change in dollars, change in percent.
2. Flag every line that changed by more than [THRESHOLD] dollars or [PERCENT] percent.
3. List every income source (payer or schedule) on last year's return that is missing this year.
4. List every new income source.
5. Check estimated payments claimed against the payments in the client file.

For each flag, write one question the preparer should be able to answer before review.
Do not explain the changes yourself. List them.

Check it

  1. The preparer answers every question on the list in the workpapers.
  2. The senior reads the answers before reviewing the return.
Where it goes wrong

A sold rental, a closed account or a retirement looks like a missing source. That's why the prompt asks for questions, not explanations: the preparer knows the client.

Workflow 5

The K-1 Tracker

At a glance
WhenWeekly from February to the extension deadlines
Who runs itSenior
Who reviews itManager
Client data that can go inTier 2: client codes, entity names and the date each K-1 arrived last year
What comes backWho's waiting on which K-1, when it's expected, and which returns it will push past the deadline

Most late returns are late for one reason: a K-1 that hasn't arrived. Last year's arrival dates tell you which ones to expect late, so the extension conversation happens in February, not on April 14.

Prompt · The K-1 board
Attached: every client who received a K-1 last year, with the issuing entity and the date the K-1 arrived; and the K-1s received so far this year.

1. Build one table: client code, entity, received this year (yes or no), date it arrived last year, expected this year.
2. Expected this year = last year's arrival date, moved to the same weekday this year. If last year's arrived after March 15, mark it LIKELY LATE.
3. For each client, the latest expected K-1 decides when the return can be finished. Sort by that date.
4. List every client whose return can't be finished before April 15 on these dates.

Give me the table and the list. Do not contact anyone.
Where it goes wrong

An entity that extended last year but filed on time this year. Update the table the day a K-1 arrives, or the list goes stale fast.

Workflow 6

The Extension Triage

At a glance
WhenFirst week of March, then weekly
Who runs itSenior
Who reviews itManager, then the partner for any payment over your threshold
Client data that can go inTier 2: the status list, last year's tax and this year's payments, by client code
What comes backWhich returns won't make April 15, the payment to send with each extension, and the email to the client

An extension extends the time to file, not the time to pay. Form 4868 moves an individual return to October 15, but tax owed is still due on April 15, so every extension needs a payment estimate and a client who knows about it.

Prompt · Who will miss April 15
Attached: the return status list (client code, documents complete yes or no, K-1 expected date from the K-1 tracker, preparer, review status), last year's total tax, and this year's estimates and withholding so far.

1. List every return that will not be filed by April 15 on the current status. Give the reason in one phrase.
2. For each one, estimate the balance due: last year's total tax, adjusted for anything the file already shows changed this year, minus payments so far. Show the working.
3. Mark each estimate HIGH, MEDIUM or LOW confidence, and say why.
4. Draft the client email: why we are extending, what they need to send, and the payment to make by April 15 with the amount.

Do not file or send anything. List anything you assumed.

Check it

  1. The manager reads every LOW confidence estimate.
  2. The partner approves any payment estimate over the firm's threshold.
  3. Check each email's amount against the working before it goes.
Where it goes wrong

A big capital gain or a year-end bonus that isn't in the file yet. The estimate is only as good as what the firm knows, which is why the email asks the client to confirm.

Workflow 7

The Notice Reader

At a glance
WhenWhenever an IRS notice arrives
Who runs itSenior
Who reviews itManager, and the partner before anything goes to the IRS
Client data that can go inTier 2: the notice and the return as filed, with identifying numbers redacted
What comes backWhat the notice says, whether the IRS is right, the response letter and the client email

A CP2000 proposes changes to a return when the income or payments reported to the IRS don't match it. Most of them are a missing 1099, a cost basis that wasn't reported, or a payment applied to the wrong year. Reading one against the return is mechanical, so let Claude do the first pass. A person decides what goes back.

Prompt · Read the notice against the return
Attached: an IRS notice for [CODE] and the return as filed for the same year.

1. What type of notice is it, what year, and what is the response date printed on it?
2. List each change the IRS proposes, with the amount, and find the matching line on the return.
3. For each change: does the return already include it (for example under a different payer name or on a consolidated statement)? Say AGREE, DISAGREE or NEED DOCUMENTS, and why.
4. Draft the response letter for each DISAGREE item, citing the return line and the document.
5. Draft a short client email: what the notice is, what we think, what we need from them, and the date.

Do not tell the client what they owe until a person has reviewed this.
Where it goes wrong

Cost basis. The notice shows gross proceeds with no basis, and the answer is on a brokerage statement page Claude didn't get. NEED DOCUMENTS is the honest answer there, so don't push it to AGREE.

Workflow 8

The Review Checklist

At a glance
WhenBefore anything is filed or sent
Who runs itManager
Who reviews itPartner signs
Client data that can go inTier 2: the return, the workpapers and the outputs of workflows 3, 4 and 6
What comes backA completed checklist with every item ticked, explained or sent back

This is the workflow that keeps the rest safe. Claude prepares the checklist from the file. A person ticks it, and nothing goes out with an open item.

Prompt · Prepare the review
Prepare the review checklist for [CODE] from the attached return, workpapers, document table (workflow 3) and prior-year comparison (workflow 4).

For each item, write DONE, OPEN or N/A, and cite the page or row:
1. Every source document in the document table is on the return.
2. Every flag from the document table has a note from the preparer.
3. Every question from the prior-year comparison has an answer.
4. Estimated payments claimed match the payments in the file.
5. Dependents, filing status and address match last year or the change is explained.
6. State returns match the federal return where they should.
7. Any extension payment made is claimed.
8. The client's Section 7216 consent is on file if any workflow used their information beyond preparing the return.

List the OPEN items first. Do not mark anything DONE that you cannot cite.
✓
Result

The reviewer starts with the open items instead of hunting for them, and the file shows who checked what.

Workflow 9

The Planning Signal List

At a glance
WhenAfter each return is prepared, and in a batch in May
Who runs itPartner, or a manager the partner names
Who reviews itPartner
Client data that can go inTier 3 where you can: codes and counts from a tax software export. Tier 2 only with the consent your adviser says this use needs
What comes backA list of clients whose returns show planning work, by signal, with a rough fee

Your team sees the planning signals every year while they prepare the return, and most of them never become a conversation. This turns the season's returns into next season's planning list.

Signal on the returnThe conversation it starts
S corporation owner, salary unchanged for three or more yearsWhether the salary still holds up as reasonable compensation, and the split between salary and distributions
Pass-through owner in a state with a PTET election, no election madeWhether electing would cut the client's federal tax
Owner profit over $400,000, no plan beyond a 401(k)Whether a cash balance plan fits
Rental on straight-line depreciation, no cost segregation studyWhether a study would move deductions forward
Capital gain over $250,000Timing, harvesting and where the next sale lands
Equity compensationWhen to exercise or sell, and what the next grant does to the year
Business sale planned within three yearsEntity, timing and structure before the sale, not after
Prompt · Build the planning list
Attached: an export from our tax software with client codes and the fields listed below. No names.

Fields: entity type, owner salary for the last three years, state, PTET election (yes or no), ordinary business income, retirement plan type, rental depreciation method, capital gains, equity compensation (yes or no), sale planned (yes or no from our notes).

1. Apply these thresholds: [FIRM THRESHOLDS].
2. For each signal, list the client codes that meet it.
3. Count unique clients across all signals.
4. At our planning fee of $[FEE], what is the total?

Give me the counts and the codes. Do not suggest a strategy for any client: a signal means a conversation is worth having, not that a strategy applies.
This list is where my work starts.

Rolling It Out

Rolling it out without stalling the season

Don't start all ten in February. Start with the ones that run before the pressure does, and add the rest as each one proves itself.

WhenWhat to do
NovemberPlan, file creation, the data rule in the WISP, the Section 7216 question to your adviser, and the projects for workflows 1, 2 and 10.
DecemberWorkflow 1 goes out. Workflow 10's baseline from last season's timesheets.
JanuaryWorkflows 2 and 3 on ten clients each, checked line by line against the old way.
FebruaryWorkflows 3 and 4 on every return. Workflow 5 weekly.
MarchWorkflow 6 in the first week. Workflow 8 on every return.

Every key date in this page is for the 2026 returns filed in 2027: W-2 and 1099-NEC by February 1, 2027 (January 31 is a Sunday); partnership and S corporation returns by March 15, 2027, or September 15 on extension; individual returns by April 15, 2027, or October 15 on extension; and the fourth 2026 estimate on January 15, 2027. Check each date with the IRS before the season.
